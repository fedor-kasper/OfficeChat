# OfficeChat Server

Сервер офисного чата: хранит аккаунты сотрудников, всю переписку и файлы и синхронизирует все устройства
человека — компьютеры, телефоны, а потом и веб-версию. Работает в локальной сети, интернет не нужен.

> Сейчас готов сам сервер. Приложения для Windows и Linux подключатся к нему на следующем этапе;
> до этого они продолжают работать между собой напрямую, как раньше.

## Что нужно

Любой компьютер в офисе, который всегда включён: Windows 10/11 или Windows Server, либо Linux (x86_64).
.NET устанавливать не нужно — сервер это один файл. Места на диске — по объёму переписки и файлов.

Файлы берутся из сборки в GitHub Actions (артефакт **OfficeChat-server**):
`officechat-server-windows-x64.exe` или `officechat-server-linux-x64`.

## Установка на Windows

1. Положите `officechat-server-windows-x64.exe` в постоянное место, например `C:\OfficeChat Server\officechat-server.exe`.
2. Откройте командную строку **от имени администратора** в этой папке и выполните:
   ```
   officechat-server install
   ```
   Появится служба «OfficeChat Server» (запускается сама при включении компьютера)
   и правила брандмауэра для портов 45680/TCP и 45681/UDP.
3. Данные лежат в `C:\ProgramData\OfficeChat Server`.

Удалить службу: `officechat-server uninstall` (данные останутся).

## Установка на Linux

```
chmod +x officechat-server-linux-x64
sudo ./officechat-server-linux-x64 install
```

Программа копируется в `/opt/officechat-server`, данные — в `/var/lib/officechat-server`,
запускается systemd-сервис `officechat-server` от отдельного пользователя `officechat`.
Если включён брандмауэр: `sudo ufw allow 45680/tcp && sudo ufw allow 45681/udp`.

Состояние и журнал: `systemctl status officechat-server`, `journalctl -u officechat-server`.

## Первый администратор

1. Откройте в браузере `https://АДРЕС-СЕРВЕРА:45680` (см. «Страница администрирования» ниже)
   и нажмите «Зарегистрироваться» — или зарегистрируйтесь в приложении, когда оно будет подключено к серверу.
2. На сервере выполните:
   - Windows (командная строка от администратора): `officechat-server admin ВАШ_ЛОГИН`
   - Linux: `sudo /opt/officechat-server/officechat-server admin ВАШ_ЛОГИН --data /var/lib/officechat-server`
3. Обновите страницу — появится список сотрудников.

Дальше права можно выдавать другим прямо со страницы администрирования.

Другие команды на сервере: `users` — список аккаунтов, `reset-password ЛОГИН` — временный пароль,
`unadmin ЛОГИН` — снять права, `help` — справка.

## Страница администрирования

Откройте в браузере `https://АДРЕС-СЕРВЕРА:45680/admin` и войдите своим логином и паролем
(на самом сервере — `https://localhost:45680/admin`). Сервер работает только по HTTPS; если набрать
адрес с `http://`, он перенаправит на `https://`.
Сертификат сервер выпускает себе сам, поэтому браузер предупредит о нём — это ожидаемо,
нажмите «Дополнительно» → «Перейти на сайт».

На странице: список сотрудников, кто в сети, сброс пароля (временный пароль показывается один раз,
устройства сотрудника отключаются), блокировка и выдача прав администратора.

## Как приложения находят сервер

Сами: широковещательный запрос в локальной сети (UDP 45681), сервер отвечает адресом и отпечатком
сертификата. Если сервер в другой подсети (например, телефоны в отдельной Wi-Fi-сети), адрес
вводится вручную. Приложение запоминает отпечаток сертификата при первом подключении и потом
доверяет только ему; сам отпечаток записан в журнале сервера при запуске.

## Обновление

Сервер обновляется сам, подключаться к его компьютеру не нужно:

- **автоматически** — раз в 6 часов он смотрит последний выпуск на GitHub (Releases) и, если там версия
  новее, скачивает её и перезапускается (приложения переподключаются сами, ничего не теряется);
- **вручную с любого компьютера** — на странице администрирования, блок «Сервер»: «Проверить обновления
  на GitHub» или «Загрузить новую версию из файла…» (файл `officechat-server-windows-x64.exe` или
  `officechat-server-linux-x64` из сборки GitHub Actions).

**Закрытый репозиторий.** Без ключа сервер выпуски не увидит. Создайте на GitHub ключ только для чтения:
Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token;
Repository access — «Only select repositories» → OfficeChat; Permissions → Repository permissions →
Contents: «Read-only»; срок — какой удобно (по окончании просто введите новый). Скопируйте ключ
(`github_pat_…`) в поле «Ключ доступа GitHub» на странице администрирования и нажмите «Сохранить».
Ключ хранится в папке данных сервера (файл `github-token`), обратно на страницу не отдаётся.
Вместо этого можно задать переменную окружения `OFFICECHAT_GITHUB_TOKEN`.

Принимается только сборка с цифровой подписью из GitHub Actions (секрет `UPDATE_SIGNING_KEY`) для этой же
системы и только более новая — подсунуть чужой файл не выйдет. Как перезапускается: служба Windows — новая
версия сама встаёт на место и запускает службу; Linux — systemd запускает новую версию (код выхода 75);
запуск из консоли — новая версия стартует с теми же параметрами (в Windows — в новом окне).

На Linux, если сервер установлен старой версией (до самообновления), один раз переустановите его новой:
`sudo ./officechat-server-linux-x64 install` — установщик отдаёт папку программы сервису, чтобы он мог
обновлять себя. Отключить автоматическую проверку: параметр `--no-auto-update`.

## Резервная копия

Всё в папке данных: `server.db` (аккаунты и переписка), `files\` (файлы), `server.pfx` (сертификат —
без него приложениям придётся заново подтверждать сервер). Копируйте папку целиком, лучше при
остановленной службе.

## Параметры запуска

```
officechat-server run [--data ПАПКА] [--port 45680] [--name "Имя сервера"] [--no-discovery] [--no-auto-update]
```

Протокол для разработчиков — [docs/SERVER-PROTOCOL.md](../docs/SERVER-PROTOCOL.md).
